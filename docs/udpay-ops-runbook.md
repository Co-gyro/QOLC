# UD Payment 運用手順書（UD社内向け）

対象: UD Payment（請求・カード自動課金）を使う加盟店（2026-10 時点: 株式会社ランサイド／モール A303）。
作成: 2026-10-19。画面はすべて https://app.qolc.jp の管理画面（管理者アカウントでログイン）。

---

## 1. 全体の仕組み（覚えておくこと）

| 誰が | 何を | どこで |
|---|---|---|
| 加盟店の担当者 | 顧客登録・請求作成・課金予約 | /billing（加盟店の画面） |
| 加盟店の承認者 | 一括実行（決済確定＋請求メール送付） | /billing → 入金管理 → 一括実行 |
| 自動（毎朝9:00） | 課金日が来た決済確定の請求を登録カードへ課金 → 結果メール | /api/cron/daily |
| UD | アカウント発行・パスワード再設定・取消／返品・問い合わせ対応 | 管理画面（/admin） |

- 課金するのは「決済確定」かつ「課金日が今日以前」の請求だけ。課金予約・下書きには絶対に課金しない。
- 1請求＝1決済。二重課金はシステムで止める（先取りロック）。
- カード番号は当社で持たない。USEN の会員ID（"U"+顧客ID）だけを持つ。

## 2. 毎日の確認（課金のある日は必須）

1. 9時過ぎに support@uni-dev.jp に届く **「【UD Payment運用】○月○日 自動課金 ○件（要対応 ○件）」** を確認する。
   - 課金が0件の日はメールは来ない。
2. 管理画面 **UD Payment → 決済の一覧・取消・返品** の上部「毎朝の自動課金」で、**最後の実行が今日になっているか**を見る。
   - 「今日はまだ実行されていません」と出ていたら、Vercel の Cron（/api/cron/daily）が動いていない。開発担当へ連絡。
3. 「要対応」（与信落ち・確認中）があれば 3 章へ。

## 3. 与信落ち・確認中への対応

| 表示 | 意味 | 対応 |
|---|---|---|
| 与信落ち | カード会社が承認しなかった（限度額・利用停止・期限切れなど） | 加盟店が顧客へ連絡 → /billing の入金管理で「再決済」。カードを変える場合は顧客に登録リンクを再送してもらい、登録後に再決済。UDの作業は通常なし（加盟店にも結果メールが届いている） |
| 確認中 | 通信の都合で結果が分からない | 翌朝の自動処理で USEN の取引照会を行い自動で確定する。急ぐ場合は開発担当へ（受注コードは決済一覧に表示） |

- 与信落ちの結果コード（決済一覧の赤字）: 02=カード利用不可（与信NG）、03=有効期限エラー、04/06/07=システム・カード会社側のエラー（顧客のカードの問題ではない → UD で確認して再決済）。

## 4. 取消・返金の依頼を受けたとき

管理画面 **UD Payment → 決済の一覧・取消・返品** で、該当の入金済みの行のボタンを押す。

| 課金からの経過 | ボタン | 内容 | 顧客の利用明細 |
|---|---|---|---|
| 課金した当日 | 取消（当日） | 売上取消＋与信取消（両方必要） | 載らない |
| 翌日以降（当日でも締め後） | 返品 | 返品（カード会社の精算後に返金） | 請求と返金の両方が載る |

- 一部だけの返金はできない。加盟店に「翌月の請求にマイナス明細を入れて相殺」を案内する。
- 課金前（決済確定の段階）なら、加盟店自身が /billing で「決済確定を取り消す」（課金日の前日まで）。
- 取消・返品は監査ログ（操作ログ・payment_audit_logs）に残る。

## 5. アカウント（加盟店の担当者・承認者）

- **新規発行**: UD Payment → 利用者のアカウント → 氏名・メール・承認者かどうか →「発行して招待メールを送る」。招待リンクは24時間有効。
- **パスワード再設定／招待の期限切れ**: 加盟店 → 該当の加盟店名（加盟店カルテ）→ 利用者 →「パスワード設定メールを送る」。メールが届かない場合は画面に出るリンクを別の方法で送る。
- **担当者⇔承認者の切り替え**: UD Payment → 利用者のアカウント →「承認者にする／担当者にする」。
- **退職などで止める**: 加盟店カルテ → 利用者 →「利用停止」（再開可能）。
- 職務分離: 課金予約した本人はその請求を一括実行できない。承認者が1人だと不在時に実行できないため、2人以上を推奨。

## 6. 顧客・カード登録まわりの問い合わせ

| 問い合わせ | 対応 |
|---|---|
| 登録リンクを無くした・届かない | 加盟店が /billing の顧客管理で「メールで送る」か「コピー」して再送（UD は管理画面 UD Payment の顧客一覧からも可） |
| カードを変えたい | 同じ登録リンクから登録し直す（上書き。次の課金から新カード） |
| 登録画面でエラー | 3Dセキュア失敗・カード不可。別のカードか、カード会社への確認を案内。1円の確認は自動で失効し請求されない |
| 本人認証の画面に知らない社名 | 決済代行の「UNIVERSAL DEVELOPMENT」と表示される旨を説明 |
| 有効期限が近い | 顧客一覧に「期限間近」の印。登録リンクで新しいカードを登録してもらう |

- 技術メモ: モール A303 はカード登録（トークン決済）だけでは USEN の会員が作られない。登録処理の中で受注コードから会員を作る対応済み（ensureMemberCard）。登録完了なのに課金で「会員なし」が出たら開発担当へ。

## 7. テストとデータの扱い

- 本番での動作確認は UD 社員のカードで少額（110円など）→ 当日中に 4 章の「取消（当日）」。
- テスト用の顧客・請求は、確認後に必ず片付ける（顧客は削除扱い、USEN の会員も削除）。加盟店の画面に見えてしまうため。
- UD 用テストアカウント（udpay-staff@qolc.test / udpay-approver@qolc.test）はログイン停止のうえ、ランサイド様の加盟店から外してある（利用人数に数えないため）。本番で使う場合は開発担当に依頼し、終わったら必ず外す。

## 8. 困ったとき

- 画面が黒い／「このアカウントでは開けない画面です」: 別の役割のアカウントでログインしたまま。ログアウトして管理者でログインし直す。
- 決済の詳しい記録: 管理画面 → 操作ログ。USEN とのやり取りはすべて payment_audit_logs に残る。
- 開発の詳細: docs/udpay-phase-c-plan-20261010.md、docs/merchant-api-runbook.md（加盟店API）。
