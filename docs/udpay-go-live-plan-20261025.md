# UD Payment 本番稼働計画 — 初回課金 10月下旬（ランサイド様・先行顧客から段階導入）

作成: 2026-09-29 ／ 前提: 9/29打ち合わせ、見積 docs/udpay-production-estimate-20260916.md

## 方針

- **初回課金を10月下旬に置き、付き合いの深い先行顧客（数件）から開始**。残りの顧客は11月以降に順次切り替え。
- 先行顧客だけなら件数が少ないので、**初回は最小構成（MVP）で開始**し、その他の要望は11月の2回目課金までに追加する。
- 初回の課金は自動実行にせず、**承認者が画面で内容を確認して実行ボタンを押す**方式にする（先行顧客の初回で誤課金を確実に防ぐため）。自動実行は2回目以降。

### 決済日について（要調整）
**2026年10月25日は日曜日**。休日の課金は、与信落ちなどの問題が起きても誰も対応できない。
→ **10月23日（金）の実行を推奨**（どちらの日も16日〜末日の決済分として翌月末日着金で、入金日は変わらない）。

## リスクと手当て

| リスク | 手当て |
|---|---|
| USEN登録が10/9に間に合わない | カード登録開始を後ろ倒し。先行顧客を2〜3件に絞れば、登録期間が短くても間に合う |
| 本番で初めて動かすUSEN接続の不具合 | 10/13〜14にUD社員のカードで本番疎通（1円与信は自動失効・少額課金は即取消） |
| 初回の誤課金 | 自動実行を使わず承認者の手動実行。実行前に一覧確認画面。作成者≠承認者をDB制約でも担保 |
| メール不達 | 本番Resendは稼働中。送付履歴（udpay_mail_logs）で確認し、念のため登録リンクを画面からコピーして手動送付も可能にする |
| 与信落ち | 初回は手動再決済＋ランサイド様から顧客へ連絡。自動再試行は11月から |
