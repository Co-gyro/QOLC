# 段階C 計画 — 本番の請求・課金（ランサイド様）

作成: 2026-10-10 ／ 前提: 段階B（本番カード登録）完了・本番疎通済み（10/9）

## ゴールと日程

ランサイド様の決済日は **15日・28日**。初回課金は **10/28（9月・10月分の請求から、先行顧客のみ）** を目標にする。

| 日付 | 内容 |
|---|---|
| 10/10〜10/16 | 実装（下記 C-1〜C-6）・migration 040 |
| 10/19（月）〜10/20 | 本番疎通: UD社員カードで **会員ID決済（A303）で少額課金 → 当日取消**。ランサイド様アカウント発行 |
| 10/21〜10/23 | ランサイド様が本番画面で操作確認（10月分の請求作成） |
| 10/26（月）まで | 承認者が一括実行（決済確定・請求メール送付）。28日分の締め |
| **10/28（水）** | 毎朝の自動課金で初回課金 → 入金管理で確認・与信落ち対応 |

10/28 に間に合わない顧客は 11/15 から。

## 方針: デモ画面をそのまま本番データで動かす

ランサイド様はデモ（/udpay）の画面と操作に合意済み（要望1〜7・追加2点）。**画面と計算ロジックは共通化**し、データの読み書きだけを本番テーブル用に差し替える。

- 本番の画面は **`/billing`**（app.qolc.jp/billing）。ランサイド様の担当者・承認者がログインして使う。
- デモ（/udpay）は残す。営業用・研修用。
- 帳票（請求書・領収証）、状態の色・凡例、月タブ、絞り込み、メールのプレビュー・編集は、デモの部品をそのまま使う。

## 実装項目

| # | 内容 | 要点 |
|---|---|---|
| C-1 | **ログインと権限** | `udpay_merchant` ロール。udpay_members で加盟店と紐付け・承認権限（is_approver）。middleware で /billing をこのロールに限定。アカウント発行はUD（SQL＋招待メール） |
| C-2 | **本番データ層** | 加盟店単位で顧客・請求・明細・決済を読み、デモと同じ形にして画面に渡す。操作（課金予約・下書きに戻す・一括実行・取消・メール編集・CSV取込・直近コピー）を本番テーブルに実装。状態は draft／submitted＝課金予約／approved＝決済確定 |
| C-3 | **職務分離** | 一括実行は承認者のみ。DB制約で「課金予約した人≠決済確定した人」（037 の chk）。承認者が1人の運用なら、担当者が課金予約→承認者が実行 |
| C-4 | **一括実行＝決済確定＋請求メール** | 確認画面（デモと同じ）→ 決済確定 → 顧客の To/CC へ請求メール（件名・追記コメント・金額等は自動差し込み）→ udpay_payments を作成（課金日＝決済日、過ぎていれば翌日）。送付履歴を記録 |
| C-5 | **毎朝の自動課金** | 既存の daily cron（毎朝9時）に追加。課金日が今日以前の `scheduled` を **条件付き UPDATE で processing に先取り**（二重課金防止）→ 受注コード採番（A303）→ `authbymemberid` → `salesadd` → captured。失敗は failed＋担当者へメール。途中で落ちた場合は取引照会で復旧 |
| C-6 | **入金管理・領収書・取消** | 入金済み・与信落ち・再決済（手動）。領収書はデモの帳票を本番データで表示。課金当日の取消・翌日以降の返品は当面UDが実施（管理画面から） |

後回し（11月以降）: 請求書PDFのメール添付（初回は本文＋画面で請求書を表示）・自動再試行・有効期限の案内（段階D）・ランサイド様自身による顧客登録画面（当面はUD代行。/billing に顧客画面は表示のみ→順次編集可に）。

## 安全策（初回課金の誤課金防止）

- 自動課金の対象は **決済確定（approved）かつ課金日到来** の請求だけ。課金予約・下書きは絶対に課金しない。
- 1請求＝1決済（udpay_payments.invoice_id UNIQUE）。処理は先取りロック（scheduled→processing の条件付き UPDATE が成功した1件だけ USEN に送る）。
- USEN 本番ホストへの送信は既存ガード（VERCEL_ENV=production か ALLOW_USEN_PROD=1）でのみ。
- 初回（10/28）は朝の自動課金後、UDが結果を確認してランサイド様へ報告。

## 先方・UDで必要なこと

- ランサイド様: 担当者・承認者の氏名とメール（返信メールで依頼済み）／先行顧客のリスト。
- UD: migration 040 の適用（メール件名・追記コメント等の列）。
