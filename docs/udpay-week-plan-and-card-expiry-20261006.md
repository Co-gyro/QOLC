## B. 本番カード登録（〜10/12）

| 項目 | 内容 |
|---|---|
| 入口 | UD管理画面（admin）に「UD Payment」→ 加盟店（ランサイド様）→ 顧客一覧。**まずはUDが代行入力でも案内を始められる**ようにし、ランサイド様ログイン（udpay_merchant）は同じ画面を加盟店単位で絞って見せる |
| 顧客 | 追加・編集（決済日・備考・社内メモ）・宛先To/CC複数・CSVでの一括登録（デモの取込を流用） |
| 登録リンク | 顧客ごとに推測できないトークン（`registration_token`）。「コピー」「メールで送る」（Resend・To/CC・送付履歴は udpay_mail_logs） |
| カード登録ページ | `/pay/udpay/[token]`（ログイン不要）。USENトークン決済（HMAC-SHA256・3DS）→ 1円確認（自動失効）→ **会員IDを udpay_customers に保存**。会員IDは QOLC の `M+uuid` と別の接頭辞 `U+uuid`。モールコードは環境変数でなく**加盟店のモールコード（A303）**から受注コードを採番 |
| 登録後 | 会員情報取得（/member/get）で**ブランド・下4桁・有効期限を保存**。カード変更（上書き登録）にも同じリンクで対応 |
| 安全策 | 本番誤送信ガード（usen-client）はそのまま。登録ページの決済は1円確認のみで課金はしない |

## D. カード有効期限の通知（QOLC・UD Payment共通）

### 仕組み（共通部品）
- **取得:** USEN「会員情報取得」（`memberGet`・既存関数）が有効期限（年・月）・マスク番号・ブランドを返す。カード番号は持たない方針のまま保存できる。
- **保存（migration 038）:**
  - `resident_accounts` に `card_brand`・`card_last4`・`card_expire_ym`（YYYYMM）・`card_checked_at` を追加。
  - `udpay_customers` に `card_last4`・`card_expire_ym`・`card_checked_at` を追加（`card_brand` はある）。
- **判定（共通の純粋関数 `src/lib/payment/card-expiry.ts`）:** 今日（日本時間）を基準に「有効／期限間近（期限月の前月・期限月）／期限切れ」を返す。テストで固定する。
- **取り直し:** カード登録・カード変更の完了時に自動で取得。既に登録済みの会員は一括取得スクリプトで埋める（QOLCの既存会員を含む）。
- **通知タイミング:** 毎朝の自動処理（既存の daily cron）で、**期限月の前月1日**と**期限月1日**に1回ずつ。同じ月に二重送信しない（送付記録で判定）。

### UD Payment（ランサイド様）
- 顧客一覧に印・絞り込み「期限間近」・ダッシュボードの「今日やること」。
- 顧客（To/CC）へカード更新の案内メール（登録リンク付き）。ランサイド担当者へ対象一覧をメールで通知。
- 一括実行の確認画面で、期限切れの顧客に警告。

### QOLC（介護施設）
- 入居者・家族へ **LINEで案内**（既存の `notifyResidentAccount` = お知らせ記録＋LINE push を使う）。本文にカード変更ページ（LIFF）へのリンク。
  LINE未連携の家族は、お知らせに記録した上で施設に一覧で知らせる（メール送信は後日）。
- 施設ポータルの入居者一覧のカード欄に「期限間近／期限切れ」の印、施設ダッシュボードに件数。
- **必要な改修:** 現在のカード登録はカード登録済みだと受け付けない（409）。「カードを変更する」として上書き登録（USENの member-modify）できるようにする。
- 家族向けの「お知らせ」画面は現状なし（`notifications` テーブルはあるが表示していない）。今回はLINEとカード画面の注意表示で足りるため、お知らせ一覧は後回し。

### 限界（先方・施設への説明に使う）
USENには、カード会社から更新後のカード情報を自動で受け取る仕組みがない。更新カードが届いても有効期限は古いまま残るため、**お客様にカードを登録し直してもらうしかない**。この機能は、その登録し直しを期限前に促すためのもの。

### 工数
共通部品＋migration 1日／UD Payment 0.5〜1日／QOLC（LINE・施設画面・カード変更）1〜1.5日 ＝ **約2.5〜3.5人日**。
ただし **B の段階で「登録時に有効期限を保存する」だけは先に入れる**（後から全件取得もできるが、最初から持っておく方が確実）。

## 今回UD側で決めたこと（ランサイド様への一覧に反映済み）
- 同じ顧客・同じ月の請求は1件。決済確定後の追加は翌月請求へ。
- 決済日が土日祝でもその日に課金。決済日は1〜28日。
- 予定日を過ぎてから決済確定した請求は、翌朝に課金。
