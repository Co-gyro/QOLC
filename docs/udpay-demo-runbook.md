# UD Payment（仮）デモ環境 — 運用手順・デモ台本

ランサイド様向け「請求書＋カード自動課金ASP」提案用のデモ環境。
QOLCリポジトリ内の `/udpay` 配下に実装（アプリ本体・qolc.jpとは独立、認証不要）。

## 常設デモ（本番・外部共有用）

```
https://app.qolc.jp/udpay?key=udpay-a481549a784b
```

- 合言葉キー付きURL。初回アクセスでCookieに保存され、以降はキーなしでOK（90日）
- キーなしアクセスは401。キーの変更は Vercel env `UDPAY_DEMO_KEY` を書き換えてRedeploy
- **顧客向けカード登録ページ（/udpay/card/…）と /api/udpay はキー不要**（登録リンクをそのまま相手に送れる）
- データは Supabase `udpay_demo_store` テーブル（1行JSONB・migration 034）。`UDPAY_STORE=supabase` で有効化
- 決済・カード会社・USENへの接続は一切なし（完全モック）。ヘッダー右上の「初期化」でシード状態に戻る
- デモ前に必ず「初期化」を押してから始めること

## ローカル起動

```bash
npm run dev
# → http://localhost:3000/udpay （キーゲートなし・ファイルストア .udpay-demo/store.json）
```

## デモデータの前提

- 顧客6件（架空の歯科医院）。ランサイド様の実請求書に合わせた品目（基本サポート¥9,900／歯科医院支援サポート¥169,800／労務管理サポート¥55,000／交通費実費）
- 2026年6月分は請求確定・全件入金済み。7月分は未作成（デモで作る）
- **みなと歯科医院**は次回課金で一度だけ与信落ち（do_not_honor）する仕込み → 再決済デモ用
- **わかば歯科**はカード未登録の新規顧客 → カード登録リンクのデモ用

## デモ台本（所要 約10分）

### 1. ダッシュボード（1分）
`/udpay` を開き「毎月の運用はこれだけ」を見せて全体像を説明。

### 2. 毎月の請求作成（3分）— 要件②③への回答
1. 「請求管理」→「前月分をコピーして下書き作成」→ 下書き5件が一瞬でできる
2. うみかぜ歯科医院を開き、**交通費の単価だけ当月実費に修正**（例: 89500）→ 合計が即時再計算
3. 「行を追加」でオプションの入替も自由なことを見せる（サブスク商品の縛りなし）
4. 「確定してメール送付・課金予約」→ 送付される請求明細メールのプレビューと「8月25日（この顧客の課金日）に自動課金」を見せる

> トーク: 「Stripeだと請求書メールと課金設定が別作業ですが、ここでは確定ボタン1つで両方終わります」

### 3. 自動課金と消込（3分）— 与信落ち対応が売り
1. 残りの下書きも確定（1件ずつ開いて確定ボタンのみ）
2. 「入金管理」→「課金バッチを実行」（実運用は課金日に自動実行。デモは手動）
3. **みなと歯科医院が与信落ち（do_not_honor）** → 赤帯の警告を見せる
   > トーク: 「実は御社のStripe明細でも、5月に同じ do_not_honor で¥587,021が3回落ちていました。現状は気づいて手で追う運用ですが、ここでは自動で検知・通知されます」
4. 「再決済」ワンクリック → 入金済みに
5. 「領収書」→ 印刷・PDF保存まで自動発行

### 4. 顧客のカード登録（2分）— カード情報非保持
1. 「顧客管理」→ わかば歯科（未登録）の「登録リンクをコピー」
   > トーク: 「このリンクをメールで送るだけ。カード番号を御社が預かることは一切ありません」
2. リンクを開き顧客視点でカード登録（テスト番号 4242 4242 4242 4242）
3. 顧客管理に戻ると「登録済み Visa」に反映

### 5. クロージング
- 移行期間: 並行稼働2〜3ヶ月、カード再登録の案内テンプレはUD側で用意
- 正直に伝える差分: Google Pay/Apple Pay非対応・入金サイト変更の可能性
- 料率は別途提示（経営側決定後）

## 実装メモ（開発者向け）

| 領域 | パス |
|---|---|
| 画面 | `src/app/udpay/`（layout/css/ダッシュボード/customers/invoices/payments/receipts/card） |
| API | `src/app/api/udpay/route.ts`（zod・action分岐） |
| ロジック | `src/lib/udpay/`（types/logic/seed/store） |
| テスト | `tests/udpay-logic.test.ts`・`tests/udpay-store.test.ts`・`tests/e2e/udpay-demo.spec.ts` |

- middleware: `/udpay` `/api/udpay` を公開パスに追加済み（認証レスで通る）＋ `UDPAY_DEMO_KEY` 設定時のみ合言葉キーゲート
- ストア: `UDPAY_STORE=supabase` でSupabase 1行JSONB、未設定でファイル（`UDPAY_STORE_DIR` で差し替え可・テストは一時ディレクトリに隔離）
- E2E: `npx playwright test tests/e2e/udpay-demo.spec.ts`（devサーバー再利用）
- 本実装（Phase移行）時は、ファイルストアを Supabase テーブル＋USEN会員ID決済APIへ差し替える。画面・フローはそのまま流用可能な設計
